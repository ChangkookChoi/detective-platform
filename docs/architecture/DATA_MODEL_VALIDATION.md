# 데이터 모델 예외 검증

- 검증일: 2026-07-22
- 데이터 성격: 실제 업체나 개인정보를 포함하지 않는 합성 표본
- 대상: 복수 지점, 공유 대표번호, 가변 깊이 지역 계층

## 목적

초기 업체 데이터를 입력하기 전에 `DATA_MODEL.md`의 핵심 결정이 예상되는 경계 사례를 구조 변경 없이 표현할 수 있는지 확인한다. 이 문서의 이름·주소·전화번호는 모델 검증만을 위한 가상 값이며 seed나 공개 데이터로 사용하지 않는다.

## 표본 A: 동일 브랜드의 복수 지점

| 항목 | 가상 강남 지점 | 가상 수원 지점 |
| --- | --- | --- |
| `offices.id` | 서로 다른 UUID | 서로 다른 UUID |
| `slug` | `sample-gangnam-office` | `sample-suwon-office` |
| 주소 | 서울특별시 강남구 가상로 1 | 경기도 수원시 팔달구 가상로 2 |
| 대표번호 | `02-000-0000` | `031-000-0000` |
| 출처 | 지점별 출처 행 | 지점별 출처 행 |

결론:

- 두 지점을 별도 `offices` 행으로 저장하면 주소, 전화번호, 공개 상태와 검수 이력을 독립적으로 관리할 수 있다.
- 브랜드 이름이 같다는 이유로 업체를 병합하지 않는다.
- 브랜드 단위 묶음이나 공통 소개가 실제로 필요해질 때만 `organizations` 도입을 검토한다.

## 표본 B: 여러 지점이 대표번호를 공유

| 항목 | 가상 성남 지점 | 가상 용인 지점 |
| --- | --- | --- |
| 주소 | 서로 다름 | 서로 다름 |
| `phone_normalized` | `0310000000` | `0310000000` |
| 공식 근거 | 각 지점 출처에서 같은 대표번호 확인 | 각 지점 출처에서 같은 대표번호 확인 |

결론:

- `phone_normalized`에는 전역 고유 제약을 두지 않는다.
- 같은 전화번호는 중복 업체 가능성을 높이는 검수 신호로 사용하되 자동 병합하지 않는다.
- 공개 전 각 지점의 주소와 전화번호에 독립적인 필드별 출처 근거를 요구한다.

## 표본 C: 경기 지역의 가변 깊이 계층

```text
경기도 (province)
├─ 수원시 (city)
│  └─ 팔달구 (district)
└─ 가평군 (county)
```

결론:

- `regions.parent_id` 재귀 관계로 `도 → 시 → 구`와 `도 → 군`을 함께 표현할 수 있다.
- 업체는 주소를 분류할 수 있는 가장 하위의 활성 지역을 참조한다. 수원 표본은 팔달구, 가평 표본은 가평군을 참조한다.
- 지역 수준을 배열 위치나 고정 깊이로 해석하지 않고 `type`과 부모 관계로 판단한다.
- 상위 지역 필터는 활성 자손 지역을 포함해야 하므로 구현 시 재귀 CTE 또는 검증된 계층 조회를 사용한다.

## 검증 결과

세 표본 모두 현재 `offices`, `regions`, `office_sources`, `office_source_evidence` 구조와 무결성 규칙으로 표현할 수 있다. 초기 migration에서 다음을 보장한다.

- 전화번호에 전역 고유 제약을 만들지 않는다.
- 지역의 자기 참조를 금지하고 애플리케이션 검증으로 순환을 방지한다.
- 업체와 출처를 지점 단위로 연결한다.
- 공개 전 필수 정보와 필드별 근거 검증은 상태 전환 유스케이스에서 수행한다.

실제 업체 표본이 확보되면 익명화된 통계로 공유 번호 빈도, 지역 깊이 분포와 중복 후보 비율을 다시 검증한다.
