# 제품 요구사항 문서(PRD)

## 1. 제품 개요

탐정사무소 정보 플랫폼은 개인 고객이 서울·경기 지역의 탐정사무소를 지역과 업무 분야로 탐색하고, 출처와 확인일이 표시된 업체 정보를 살펴본 뒤 무료 전화 연결을 시도할 수 있게 한다. 첫 제품은 거래 중개가 아닌 정보 디렉터리이며, 데이터 신뢰와 탐색 수요를 검증한 뒤 상담·견적·업체 참여 플랫폼으로 확장한다.

## 2. 문제

- 업체 정보가 여러 사이트에 흩어져 있어 비교에 시간이 든다.
- 상호, 주소, 전화번호, 제공 업무가 최신인지 판단하기 어렵다.
- 광고와 일반 정보의 경계가 불명확하면 사용자가 추천이나 순위로 오인할 수 있다.
- 민감한 사정을 다루는 이용자는 상세 사건 내용을 남기지 않고 직접 연락하기를 원할 수 있다.

## 3. 목표

- 서울·경기 약 100개 업체의 최소 핵심 정보를 검증하여 제공한다.
- 지역과 업무 분야를 기준으로 목록에서 상세 정보까지 빠르게 이동하게 한다.
- 각 업체 정보의 출처와 최종 확인일을 이해하기 쉽게 표시한다.
- 별도 가입이나 결제 없이 전화 연결을 제공한다.
- 상세 조회와 전화 버튼 클릭을 업체 단위로 집계해 제품 수요를 학습한다.
- 자동 수집과 사람의 검수를 결합해 오래된 정보의 공개 위험을 낮춘다.

## 4. 비목표

- 탐정 업무의 적법성, 품질, 성과를 보증하거나 특정 업체를 추천하지 않는다.
- 사용자의 사건 내용이나 조사 대상자 정보를 접수하지 않는다.
- 회원가입, 채팅, 결제, 후기, 별점, 업체 순위를 제공하지 않는다.
- 전화 연결에 과금하지 않으며 통화 내용과 녹취를 저장하지 않는다.

## 5. 핵심 사용자

### 개인 고객

외도·가족 문제 등 개인적인 사안으로 업체를 찾으며, 가까운 지역, 취급 업무, 연락 방법과 정보의 신뢰 근거를 빠르게 확인하려는 사용자다.

### 운영 관리자

수집된 후보 정보와 변경 사항을 출처 원문과 비교하고, 공개·수정·보류·반려를 결정한다.

### 업체 담당자(초기 간접 사용자)

공개된 업체 정보의 정정을 요청하거나 광고·강화 상품에 관심을 가질 수 있다. 초기에는 셀프서비스 계정을 제공하지 않고 운영자가 요청을 처리한다.

## 6. 핵심 가치 제안

- 사용자: 민감한 내용을 제출하지 않고도 검증 시점이 표시된 업체 정보를 찾고 바로 연락한다.
- 운영자: 자동 수집 후보와 변경 이력을 이용하되 승인된 정보만 공개한다.
- 업체: 정확한 기본 정보로 발견될 수 있고, 명확히 표시된 광고·강화 상품을 선택할 수 있다.

## 7. 기능 요구사항

### 탐색과 상세

- 공개 목록은 승인되고 공개 상태인 업체만 노출한다.
- 지역(서울/경기와 하위 행정구역) 및 업무 분야로 필터링할 수 있다.
- 초기 지역 필터는 업체가 서비스를 제공한다고 주장하는 범위가 아니라 검수된 사무소 소재지를 기준으로 한다.
- 공개 업체 한 건은 하나의 실제 사무소 또는 지점을 나타낸다. 같은 브랜드의 지점도 주소나 대표 연락처가 다르면 별도 항목으로 관리한다.
- 업체명, 대표 지역, 취급 업무, 요약, 전화 연결 동선을 제공한다.
- 상세에는 주소, 전화번호, 업무 분야, 소개, 영업 관련 공개 정보, 출처, 최종 확인일을 가능한 범위에서 표시한다.
- 정보가 없거나 검증되지 않은 값은 추정하지 않고 미표시 또는 확인 필요로 표현한다.

### 전화 연결

- 모바일 등 지원 환경에서 `tel:` 링크로 연결한다.
- 초기에는 업체별로 검수된 대표 전화번호 한 개만 공개한다.
- 연결 버튼을 누르면 전화번호와 함께 무료 연결이며 통화료는 통신사 정책에 따를 수 있음을 명확히 한다.
- 서비스는 연결 자체에 비용을 부과하지 않는다.
- 클릭 이벤트는 최소 정보로 집계하며 통화 성립 여부, 내용, 녹취는 수집하지 않는다.

### 신뢰와 정정

- 가능한 모든 업체 정보에 출처 URL과 최종 확인일을 제공한다.
- 정보 오류 신고 또는 업체 정정 요청 경로를 제공하되 사건 내용을 받지 않는다.
- 자동 수집 결과와 중요 변경은 관리자 승인 전 공개하지 않는다.

### 관리자 검수

- 신규 후보와 필드 변경을 원문, 이전 운영값, 수집 시각과 함께 비교한다.
- 지원하는 자동 추출 구조가 없는 공식 공개 출처는 인증된 운영자가 상호,
  대표 전화와 주소만 수동 신규 후보로 등록할 수 있다.
- 승인, 수정 후 승인, 보류, 반려와 사유를 기록한다.
- 상호, 전화번호, 주소, 폐업 후보는 항상 명시적 검수 대상으로 둔다.
- 수집 실패나 소스 삭제가 기존 공개 데이터를 자동 삭제하지 않게 한다.
- 수동 등록도 제출 즉시 업체를 만들거나 공개하지 않으며 제출자 ID와 출처를
  추적한다.
- 사전검증된 공식 후보 묶음은 운영자가 행별 값을 확인한 뒤 정상 건만 선택해
  일괄 승인할 수 있다. 배치 동작도 업체별 독립 검수·감사·출처 근거를 남긴다.

### 분석

- 업체 상세 조회와 전화 버튼 클릭을 일별·업체별로 집계할 수 있다.
- 공개 순위 산정에 사용하지 않는다.
- 광고 성과와 일반 탐색 지표를 구분한다.

## 8. 수익 모델 원칙

초기 수익 모델은 광고와 업체용 강화 상품이다. 유료 노출은 눈에 띄게 `광고` 또는 이에 준하는 문구로 표시하고, 결제 여부가 일반 목록의 객관적 순위나 품질 보증으로 해석되지 않도록 한다. 초기 제품 안에서 온라인 결제를 제공하지 않으며 계약·청구는 별도 운영 절차로 처리한다.

## 9. 성공 지표

출시 전 기준:

- 공개 업체 수 및 중요 필드 검수 완료율
- 출처 URL 보유율과 최근 확인 기준 충족률
- 공개 전 관리자 승인 누락 건수 0건
- 핵심 페이지 접근성·SEO·보안 점검 통과

출시 후 관찰 지표:

- 목록에서 상세로 이동한 비율
- 상세 페이지에서 전화 버튼을 누른 비율
- 지역·업무 분야별 검색 결과 없음 비율
- 정보 정정 요청률과 처리 시간
- 수집 변경 후보의 승인·반려·보류 비율

수치 목표는 실제 트래픽 기준선 확보 후 별도 문서에서 정한다. 클릭은 통화 성립이나 계약 성사를 의미하지 않는다.

## 10. 출시 조건

- 핵심 사용자 흐름이 모바일과 데스크톱에서 동작한다.
- 공개 데이터가 검수 정책과 데이터 모델을 따른다.
- 관리자 경로는 인증·권한 검사를 적용한다.
- 개인정보 처리방침, 이용 안내, 광고 표시, 정정 요청 경로가 준비된다.
- robots, sitemap, canonical, 구조화 데이터가 실제 공개 상태와 일치한다.
- 장애·오정보·보안 사고 대응 담당과 절차가 정해진다.

## 11. 향후 확장 원칙

상담 접수, 복수 견적, 업체 계정, 결제 같은 기능은 사용자 수요, 법적 검토, 개인정보 영향 평가, 운영 역량을 확인한 뒤 별도 PRD와 ADR로 결정한다. 디렉터리 단계의 공개 데이터와 민감한 상담 데이터가 향후에도 같은 경계로 취급되지 않도록 분리 설계를 우선한다.
