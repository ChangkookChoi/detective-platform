## 현재 구현

### 공개 웹·관리자

- Next.js App Router와 PostgreSQL 기반 공개 업체 목록·지역/업무 필터·상세·전화
  연결, 출처·확인일, 개인정보 최소화 조회/클릭 집계와 정정 요청을 구현했다.
- 공개 지역 seed와 필터를 서울·경기·인천 94개 계층으로 확장했다. 인천은
  2026년 7월 1일 시행된 2군·9구 체계를 사용하며 폐지된 중구·동구와 개편 전
  서구를 신규 분류로 사용하지 않는다.
- Clerk Hobby Development의 실제 Google 로그인과 `reviewer`/`admin` 서버 권한,
  신규·변경·정정 후보의 승인·수정 후 승인·보류·반려 및 감사 이력을 검증했다.
- 공식 후보 manifest 일괄 등록·선택 승인과 공식 출처 최소 사실 비교, 안전한
  새 창 원문 링크, 위험도·검수 종류·발생 사유 설명을 제공한다.
- 24시간 이내 공식 최소 사실이 모두 일치한 discovery 후보를 기본 dry-run과
  명시적 로컬 `--apply`로 `pending/new_office/high` 검수 큐에 멱등 적재한다.
  실제 후보 식별정보는 CLI에 출력하지 않고 Clerk 제출자와 공식 확인 실행을
  감사 스냅샷에 남긴다.
- 외부 공식 홈페이지를 관리자 화면 `iframe`으로 실행하거나 자동 수집값을
  관리자 승인 없이 공개하지 않는다.

### 데이터·운영

- 개발 DB 공개 업체는 기존 서울·경기 64건이며 Production Neon은 32건이다.
  인천은 검색·검수 가능한 공개 범위에 포함됐지만 아직 승인 공개된 업체는 없다.
- PostgreSQL migration·seed, 최소 권한 runtime/collector/backup 역할, age 암호화
  GitHub Actions 백업과 실제 PostgreSQL 17 복원 리허설을 구현했다.
- 공식 업무용 이메일은 선택 정보로 검수하되 공개 이메일과 메일 발송 동의를
  분리한다. 개발 DB의 이메일 변경 검수는 28건, 마케팅 동의는 0건이다.
- Vercel Hobby·Neon Free 비용 경계를 유지한다. custom domain과 Clerk live 키가
  없어 아직 공개 출시 상태가 아니다.

### 수집기

- Python 3.13·uv, 정책 allowlist, 공개 IP·HTTPS·redirect·robots·응답 크기·timeout·
  제한 재시도, JSON-LD/보이는 HTML 최소 사실 추출과 변경 감지를 구현했다.
- NAVER API HUB 지역·웹문서 검색은 [ADR-0010](decisions/ADR-0010-naver-api-discovery-pilot.md)의
  제한적 비상업 파일럿이다. Raw/filtered/facts는 Git 제외 `data/private`에 `0600`,
  기본 7일로 보존하며 AI 입력·공개 화면·Production에 전달하지 않는다.
- 전국 지역 API Raw 3,144건에서 비반려 고유 후보 1,005건을 확보해 비공개 후보
  500곳 목표를 달성했다. 이는 검증 또는 공개 업체 수가 아니다.
- 필터 v4는 명시적 오락·동물·건설·무관 전문업 문맥이 검색 카테고리로 상쇄되지
  않게 한다. `audit-naver-discovery-filter`는 기존 결과와의 상태 변화를 후보
  식별정보 없이 비교한다.
- `scripts/run-naver-discovery-cycle.sh`는 지역 발견 → 직접 링크 우선 처리 → 제한된
  웹 보강 → 정책 probe → 최소 사실 추출 → 검토/추가 조사 분리 → 사유별 라우팅·
  동일 도메인 보강을 한 번에 실행한다.
- 추가 조사 중 지점·상호 충돌은 사람에게 남긴다. 전화·사실·업무 증거만 부족한
  후보는 공식 시작 페이지가 연결한 같은 도메인의 최대 3페이지만 다시 확인하며
  결과도 `promotion_allowed=false`다.

## 2026-08-25 재검증 결과

  유지됐다.
- 최신 전국 100개 지역·`탐정사무소` 표본은 API 100회, Raw 489건이었다. 실행 내

- 공식 링크 44건의 정책·네트워크 probe 결과는 본문 확인 가능 10건, 수동 정책

- 본문 10건은 강한 사실 일치 4건, 부분 일치 5건, 정보 부족 1건이며 공식 탐정

  22건은 각각 11건·11건이다. 자동 보강 가능 13건의 공식 페이지 21개를 추가
  확인했지만 모든 부족 사유를 해소한 후보는 0건이므로 무제한 확대하지 않는다.
- 이번 작업은 개발·Production DB를 변경하지 않았다. 신규 비공개 파일의 만료는

## 2026-08-26 인천 범위·discovery intake 검증

- 신규 `office-discovery-review-v3` intake는 NAVER 후보 상호·주소 대신 공식
  홈페이지에서 추출·대조된 상호·상세 주소를 사용하고 서울·경기·인천 주소만
  허용한다. 공식 주소에서 최하위 지역을 결정론적으로 제안하되 관리자가 승인
  화면에서 확인하고 최종 결정하는 경계는 유지한다.
- Git 제외 `0600` JSONL만 읽고 상호·상세 주소·대표 전화·지역 일치와 탐정 업무
  근거가 모두 참인 24시간 이내 레코드만 허용한다. 기본 dry-run, 명시적
  `--apply`, Clerk reviewer/admin actor, 로컬 PostgreSQL 제한과 공개·미해결 후보
  중복 검사를 구현했다.
- 임시 PostgreSQL 17에서 dry-run 무변경, 최초 `pending/new_office/high` 1건 적재,
  같은 입력 재실행 시 추가 생성 0건을 확인했다. 전체 로컬 migration·seed·웹 DB·
  수집기 권한/통합 검증도 통과했다.
- 최신 실제 비공개 큐 dry-run은 적재 가능 1건, 공개·미해결 중복과 제외 0건이었다.
  이를 지속형 개발 DB에 한 번 적재했고 같은 입력 재실행은 미해결 중복 1건으로
  건너뛰었다. 독립 조회 결과 공개 업체는 계속 64건, discovery 검수는
  `pending/new_office/high` 1건, 감사 제출자 권한은 유효하며 검수 작업은 0건이다.
- 기존 검수 1건은 v2로 생성된 감사 스냅샷을 유지한다. 공식 표기 `SG탐정법인`,
  이메일 없음, `인천광역시 연수구 새말로96번길 30 202호(이강빌딩)`을 원문과
  대조해 수정 후 승인할 수 있고, 주소 기반 기본 지역은 인천 연수구다.
- 개발 DB seed를 82개에서 94개로 멱등 확장했고 정적 seed·PostgreSQL 통합 검증,
  SG 주소의 `incheon-yeonsu` 제안 단위 테스트를 통과했다.
- Production 데이터와 공개 업체 값은 변경하지 않았다. 관리자는 공식 원문에서
  정확한 최하위 지역, 관리형 업무 분야와 공개 slug를 선택한 뒤에만 이 후보를
  승인할 수 있다.

   연수구 소재, 공식 상호, 관리형 업무 분야와 공개 slug를 사람이 확인해 승인·
   수정 후 승인·보류·반려한다. 전국 후보는 공개 지역 범위를 자동 확장하지 않는다.
3. 지점·공유 출처 충돌 15건은 공식 페이지가 지점별 정확한 주소와 대표번호를

   자동 적재하지 않고 사유별 조사 큐에 유지한다.

## 현재 제한과 경계

- 서울·경기·인천 공개 약 100곳이 MVP 목표다. 전국 후보는 비공개 상태만 포함한다.
- 사용자 회원가입, 사건 접수, 채팅, 결제, 후기·별점·순위, 전화 과금·녹취와
  대량 이메일 발송은 현재 범위가 아니다.
- NAVER 검색 결과와 파생 파일은 AI 입력, Git, CI artifact, 공개 화면과
  Production에 전달하지 않는다.
- 수집 실패·404·출처 삭제는 기존 공개값의 수정·삭제로 자동 전파하지 않는다.
- 공식 이메일 수집은 발송 동의가 아니다. 동의 없는 대량 발송 기능은 구현하지
  않는다.
- Production 32건 이후 개발 DB 신규분은 별도 사용자 승인·사전 암호화 백업 없이
  승격하지 않는다.

## 검증 기준

- Python 변경: `uv run python -m compileall -q collector main.py tests`와 전체 단위
  테스트를 통과해야 한다.
- 웹 변경: lint, webpack Production build와 영향 범위 E2E를 통과해야 한다.
- 문서 변경: 상대 링크, 후행 공백과 `git diff --check`를 확인한다.
- 공개/Production 데이터 수는 독립 DB 조회로 확인한 사실만 갱신한다.

기능 범위, 구현 단계, 배포 상태나 핵심 위험이 바뀌면 이 문서를 먼저 갱신한다.
과거 세부 실행 기록은 스냅샷 문서에서 보존하되 현재 구현 판단에는 이 문서를
우선한다.
