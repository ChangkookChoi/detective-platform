# 프로젝트 상태

- 기준일: 2026-07-22
- 단계: 핵심 MVP 기능 구현
- 배포 상태: 미배포
- 데이터 상태: 실제 업체 데이터 미등록

## 현재 요약

서울·경기 약 100개 탐정사무소를 대상으로 하는 정보 디렉터리 MVP의 공개 탐색과 관리자 검수 흐름을 구현하고 있습니다. 데이터 계층, 홈·목록·상세, Clerk 인증 검수, 개인정보 최소화 일별 집계, 정책 기반 Python 수집기에 이어 신규 수집 후보의 운영 업체 생성과 기존 업체의 수정 후 승인까지 구현했습니다. PostgreSQL 17 합성 데이터로 수집 후보부터 출처·근거·감사 이력·공개 전환의 원자성과 실패 롤백을 통합 검증했으며, 지속형 개발·운영 DB, 실제 출처 정책·업체 데이터와 운영 인증 키는 준비 전입니다.

## 확정된 초기 데이터 모델

- 공개 업체 한 건은 하나의 실제 사무소 또는 지점이며 복수 지점은 별도 항목으로 관리
- 소재 지역 한 개와 대표 전화번호 한 개를 업체에 저장
- 주소는 표시 문자열과 검색용 지역 참조로 시작
- 지역 검색은 서비스 가능 지역이 아닌 검수된 소재지 기준
- 업무 분야는 개인 고객 중심의 다섯 가지 관리형 초기 분류 사용
- 업체 출처와 함께 필드별 출처 근거를 기록
- `draft`, `published`, `suspended`, `closed_suspected`, `archived` 공개 상태 사용

- 사용자 회원가입 및 사용자 프로필
- 사건 내용 접수 또는 조사 대상자 정보 수집
- 채팅, 결제, 후기, 별점, 업체 순위
- 전화 연결 과금, 통화 내용 또는 녹취 저장
- Elasticsearch/OpenSearch, Spring Boot, 마이크로서비스 도입
- 관리자 승인 없는 자동 공개

## 현재 검증 제한

- 초기 migration과 seed는 PostgreSQL 17.10 임시 클러스터에서 검증했지만 지속형 개발 DB와 운영 DB 공급자·연결 풀링·백업 방식은 아직 결정하지 않았다.
- Clerk 개발·운영 키와 실제 관리자 계정이 없어 로그인 UI, 세션과 역할 allowlist의 실제 공급자 연동은 아직 검증하지 않았다. 권한 판정과 검수 데이터 흐름은 합성 ID·데이터로 검증했다.
- 수집기는 고정 JSON-LD와 mock HTTP로 검증했으며 실제 출처 이용 조건·robots 확인, 사이트별 구조, 운영 네트워크·최소 권한 DB 역할, 예약 실행과 알림은 아직 검증하지 않았다.
- 현재 자동화 환경에서 인앱 브라우저를 사용할 수 없어 분석 Client Component의 실제 페이지 표시·클릭 네트워크 요청은 시각 검증하지 못했다. 동일 요청 계약의 Route Handler부터 PostgreSQL 집계까지는 합성 HTTP 요청으로 통합 검증했다.
- 2026-07-22 `npm audit` 기준 중간 5건, 높음 2건이 보고됐다. Next.js 간접 의존성의 `sharp`·`postcss`와 Drizzle Kit 개발 의존성의 구형 `esbuild` 경로이며, 제안된 자동 수정은 호환되지 않는 주요 버전 하향이어서 적용하지 않았다.

## 상태 갱신 규칙

기능 범위, 구현 단계, 배포 상태 또는 핵심 위험이 달라질 때 이 문서를 갱신합니다. 완료 여부는 코드 존재가 아니라 검증 가능한 사용자 흐름과 운영 준비 상태를 기준으로 판단합니다.
