# 공식 업무용 이메일 운영 정책

## 목적

업체 공식 홈페이지에서 업무 연락처로 공개한 이메일을 업체 정보 확인과 향후
동의 기반 연락에 사용할 수 있도록 검수한다. 이메일 수집 자체를 광고성 메일
발송 동의로 해석하지 않는다.

## 수집 범위

- 허용: JSON-LD `email`, 공식 페이지의 `mailto:`, 연락처·푸터에 보이는 단일
  업무용 이메일
- 보류: 담당자 이름 기반 주소, 무료 메일 주소, 업무용인지 불분명한 주소
- 제외: 사건·상담 내용 안의 주소, 고객·조사 대상자 이메일, 제3자 디렉터리에서만
  발견된 주소, 복수 주소가 한 문자열에 섞인 값, 추정·조합한 주소

수집기는 주소를 생성하거나 도메인 패턴으로 추측하지 않는다. HTML 전문은
저장하지 않고 이메일, 출처 URL, 확인 시각과 판정만 검수 후보에 남긴다.
현재 등록 업체와 대기 후보 보강은 NAVER API가 아니라 DB의 공식 출처 URL을
정책 기반으로 직접 확인하는 `collect-office-emails` 명령을 사용한다. 결과는
Git 제외 `data/private/email-runs`에 기본 7일 보관하며 이메일 전문을 CLI나
AI 입력에 전달하지 않는다.

## 검수와 저장

1. 공식 운영 주체가 직접 관리하는 공개 페이지인지 확인한다.
2. 이메일이 업체의 업무 연락처로 표시됐는지 확인한다.
3. 정규화값, 표시값, `generic_business` 또는 `unknown` 유형을 비교한다.
4. 승인된 값만 `offices`와 공식 출처의 `email` 근거에 반영한다.
5. 누락·접근 실패·원문 삭제는 기존 승인 이메일을 자동 삭제하지 않고 변경
   후보로만 다룬다.

이메일은 선택 항목이고 현재 MVP 공개 화면에는 표시하지 않는다.

## 메일 발송 경계

- `office_email_marketing_consents` 행이 없으면 발송 동의가 없다.
- 공식 이메일 수집기와 관리자 후보 승인 코드는 동의 행을 만들지 않는다.
- `consented`에는 명시적 동의 출처와 동의 시각이 필요하다.
- `unsubscribed`는 모든 후속 발송에서 제외한다.
- 업무 협업이라는 제목만으로 비광고성이 확정되지 않는다. 입점·제휴·광고·유료
  상품 등 사업상 이익 제안이 포함되면 광고성 정보 규정을 적용할 가능성을
  검토한다.
- `(광고)` 표시, 전송자 정보와 간편 수신거부는 필요한 경우의 형식 요건이며,
  사전 동의가 필요한 상황에서 이를 대신하지 않는다.
- 대량 발송 기능을 구현하기 전 별도 법률 검토, 발송 ADR, 수신거부 즉시 반영과
  감사 로그 검증을 완료한다.
