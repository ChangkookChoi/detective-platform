# 최소 분석 이벤트 운영

## 1. 목적

업체 상세 조회와 전화 버튼 클릭을 개인정보 없이 업체별·일별로 집계하는 운영 기준을 정의한다. 저장 방식의 선택 근거는 [ADR-0006](../decisions/ADR-0006-privacy-minimal-analytics.md)을 따른다.

## 2. 이벤트 의미

| 이벤트 | 기록 시점 | 의미하지 않는 것 |
| --- | --- | --- |
| `office_detail_view` | 공개 상세가 브라우저에서 표시된 뒤 | 고유 사용자, 상담 또는 계약 |
| `phone_click` | 사용자가 공개 전화 링크를 선택할 때 | 통화 앱 실행 성공, 통화 성립, 계약 |

같은 브라우저 탭 세션에서 같은 업체·이벤트는 한국 날짜별 한 번만 집계한다. 따라서 수치는 원시 요청 수가 아니라 중복을 줄인 보수적인 관심 신호다.

## 3. 수집하지 않는 값

- 원시 IP와 IP 해시
- User-Agent와 브라우저 지문
- Referrer와 전체 방문 URL·검색 쿼리
- 전화번호와 전화 앱 실행 결과
- 로그인 사용자 ID, 이름, 이메일
- 사건 내용, 조사 대상자 정보와 통화 내용

클라이언트가 만드는 임의 세션 UUID는 탭의 `sessionStorage`에만 두고 서버에는 원문을 저장하지 않는다.

## 4. 중복·속도 제한·봇 정책

- API는 같은 출처의 `application/json` POST만 허용한다.
- 공개 상태 업체의 허용된 두 이벤트만 기록한다.
- 서버는 세션 UUID를 해시해 업체·이벤트·한국 날짜별 중복 키를 만든다.
- 같은 세션은 한국 날짜 기준 최대 50개의 서로 다른 이벤트를 기록할 수 있다.
- 중복 요청은 성공으로 응답하지만 일별 합계를 올리지 않는다.
- 제한 초과는 `429`로 응답한다.
- 분석 API 실패는 상세 화면 표시와 전화 링크 동작을 막지 않는다.

이 정책은 단순 중복과 저비용 봇을 줄이는 장치다. IP, 장기 쿠키나 브라우저 지문을 쓰지 않으므로 의도적인 조작을 완전히 제거하는 정책으로 해석하지 않는다.

## 5. 보존과 집계

- `office_daily_metrics`: 업체, 한국 날짜, 상세 조회 수와 전화 클릭 수를 영속 보관한다.
- `analytics_events`: 중복·속도 제한을 위한 최소 행만 48시간 유지한다.
- 이벤트 기록 시 48시간이 지난 중복 방지 행을 삭제한다.
- 일별 합계와 단기 행 어디에도 전화번호, IP, User-Agent 또는 세션 UUID 원문을 저장하지 않는다.

출시 전 개인정보·법무 검토에서 일별 집계의 보존 기간과 삭제 절차를 확정한다. 광고 지표는 일반 탐색 지표와 같은 열이나 이벤트로 섞지 않는다.

## 6. 운영 점검

- 공개되지 않은 업체 이벤트가 저장되지 않는지 확인한다.
- 중복 이벤트가 합계를 반복 증가시키지 않는지 확인한다.
- 단기 이벤트가 48시간 뒤 정리되는지 확인한다.
- 비정상적인 `400`, `403`, `429`, `500` 비율을 비민감 상태 코드 중심으로 관찰한다.
- 상세 조회 대비 전화 클릭 비율을 통화 또는 계약 성사율로 표현하지 않는다.
- 업체별 수치를 공개 순위, 추천, 품질 점수에 사용하지 않는다.
