# NAVER API HUB 기반 업체 발굴 관련 전문가 검토 요청서

- 작성일: 2026-08-20
- 최근 사실관계 갱신: 2026-08-21
- 대상 서비스: 탐정사무소 정보 플랫폼
- 검토 목적: NAVER API HUB 검색 API를 업체 후보 발굴에 사용하는 방식이
  계약·약관·저작권·데이터베이스권·부정경쟁·개인정보 및 상업적 이용 제한에
  부합하는지 확인
- 문서 성격: 법률 의견이 아닌 현재 사실관계와 검토 질문의 정리

## 1. 검토가 필요한 핵심 사안

서비스는 서울·경기 탐정사무소의 상호, 사무실 주소, 사업상 대표 전화번호,
업무 분야와 공식 출처를 검수해 제공하는 정보 디렉터리다. 현재 공개 데이터의
기준 출처는 각 업체의 공식 홈페이지 등 공개된 공식 출처다. NAVER API HUB는
2026-08-20~21 비상업 파일럿의 내부 후보 발견에 실제 사용했지만 API 결과를
공개 근거나 운영 DB 값으로 사용하지 않았다.

2026-08-20 NAVER API HUB의 `지역` 및 `웹문서` 검색 API를 사용할 Application과
인증 정보를 준비했다. 애초에는 검색 API로 대량 후보를 발견하고, 검색 결과를
코드로 정규화·중복 제거한 뒤 소수 후보만 AI가 검수하도록 설계하려 했다.

그러나 네이버가 공지한 2026-09-07 시행 예정 검색 API 특약은 검색 결과의
저장·가공·파생물, 제3자 제공, AI 입력과 수익 목적 사용을 광범위하게 제한한다.
운영자는 위험을 인지한 상태에서 전문가 검토 전 제한 파일럿을 진행하기로
결정했다. 아래에는 원래 계획뿐 아니라 실제 호출·임시 저장·필터 범위를 함께
기록한다. 이는 해당 이용이 약관상 허용된다는 판단을 뜻하지 않는다.

## 2. 서비스 현황과 사업 모델

### 2.1 현재 범위

- 서울·경기 소재 탐정사무소를 지역·업무 분야별로 탐색하는 공개 디렉터리
- 업체명, 정확한 한 사무실 주소, 사업상 대표 전화번호 한 개, 업무 분야,
  공식 출처 URL과 최종 확인일을 표시
- 무료 `tel:` 전화 연결 제공
- 사건 내용, 조사 대상자 정보, 통화 내용과 녹취는 수집하지 않음
- 후기, 별점, 업체 순위, 온라인 결제는 현재 제공하지 않음
- 자동 또는 수동으로 발견한 업체는 관리자 승인 전까지 공개하지 않음

2026-08-20 현재 개발 DB의 공개 업체는 64곳이고 Production DB는 32곳이다.
별도로 공식 출처를 확인한 10곳의 비공개 등록 준비 배치가 있으며, 이 10곳은
NAVER API HUB로 수집한 데이터가 아니다.

### 2.2 수익화 계획

초기 수익 모델로 광고와 업체용 강화 상품을 검토하고 있다. 현재 온라인 결제는
없지만, 향후 디렉터리 화면에 광고 또는 유료 강화 노출이 포함될 가능성이 있다.
검색 API 결과 또는 그 파생 정보가 이러한 상업 서비스의 업체 데이터 확보에
사용되는 것만으로 약관상 `수익을 얻는 행위`에 해당하는지가 핵심 질문이다.

## 3. 현재 업체 데이터를 확보하는 방식

### 3.1 사람이 보조하는 공개 웹 조사

현재 데이터 확대의 주된 방식은 AI 코딩 에이전트가 일반 웹 검색으로 후보를
발견하고, 검색 결과 자체를 공개 근거로 쓰지 않은 채 각 업체의 공식 홈페이지를
직접 확인하는 방식이다. 공식 페이지에서 현재 공개된 최소 사실만 정리한다.

- 업체명 또는 공식 운영 주체명
- 서울·경기의 정확한 사무실 주소
- 사업 목적으로 공개된 대표 전화번호
- 공식 페이지에서 직접 확인되는 업무 분야
- 공식 출처 URL과 확인 시각

동일 상호, 전화번호, 주소, 공식 URL과 도메인을 기존 DB 및 출처 등록부와
대조한다. 주소나 운영 주체가 충돌하거나 공식성을 확인하지 못한 후보는 보류 또는
제외한다. 블로그, 카페, 후기와 홍보성 디렉터리는 업체를 발견하는 단서가 될 수
있지만 현재 공개 정보의 대표 출처로 사용하지 않는 것이 원칙이다.

이 과정에서는 AI가 공개 웹 페이지를 검토해 구조화 후보와 근거 메모를 만든다.
다만 현재까지 NAVER 검색 API 응답을 AI에 입력한 적은 없다.

### 3.2 정책 기반 Python 수집기

별도의 Python 수집기에는 두 경로가 있다. 기존 운영 경로는 사람이 승인한 공식
홈페이지의 개별 URL만 allowlist로 등록해 순차 요청한다. 이번 NAVER 파일럿
경로는 API 검색 결과를 7일 임시 파일로 격리하고, 결정론적 필터 뒤 공식 URL의
정책과 최소 사실을 다시 확인하지만 자동 운영 후보나 공개 데이터로 만들지 않는다.

- HTTPS host와 path를 사전 허용 목록으로 제한
- 공개 IP 여부와 redirect 대상을 매 단계 검사
- robots와 이용 정책을 사람이 확인한 뒤 실행
- 출처별 요청 간격, timeout, 제한된 재시도와 최대 응답 크기 적용
- JSON-LD에서 허용된 `name`, `telephone`, `address`, `description`만 추출
- 원문 HTML 전체를 파일로 보존하지 않음
- 수집 결과를 공개 업체 행에 직접 반영하지 않고 비공개 검수 후보로만 저장
- 누락·오류·원문 삭제가 기존 공개 데이터를 자동 변경하거나 삭제하지 않음

### 3.3 사전검증과 공개 승인

사람 또는 자동 수집기로 만든 후보는 다음 절차를 거친다.

1. Git에서 제외된 `data/private`의 배치 manifest에 최소 사실과 근거를 기록
2. HTTPS, robots, 공개 IP, 접속 상태, 호스팅 만료 징후를 사전검증
3. DB의 이름·전화번호·주소·slug·출처 URL 중복 검사
4. Clerk로 인증한 관리자가 원문과 값을 대조
5. 승인, 수정 후 승인, 보류 또는 반려 결정과 처리자·사유 기록
6. 승인된 값만 공개 업체, 대표 출처와 필드별 근거로 반영

## 4. 현재 저장·공개하는 정보

### 4.1 저장·공개 대상

- 업체명과 slug
- 정확한 한 사무실 주소와 지역 분류
- 사업상 대표 전화번호 한 개
- 관리형 업무 분야 분류
- 짧은 소개 또는 최소 근거 메모
- 공식 출처 URL, 출처 유형, 확인 시각
- 관리자 검수 상태, 결정 사유와 감사 처리자

### 4.2 수집하지 않는 대상

- 고객의 사건 내용과 조사 대상자 정보
- 통화 내용과 녹취
- 출처에 표시된 후기·별점·성과 주장
- 대표자 개인 프로필 등 서비스 목적에 불필요한 개인정보
- 계정 정보, 세션, 제한·유료 콘텐츠
- 공식 페이지 원문 전체와 이미지의 복제본

## 5. NAVER API HUB 이용 방식

Application에는 `NAVER 검색 > 지역`과 `NAVER 검색 > 웹문서`가 등록돼 있다.
Client ID와 Client Secret은 로컬 Git 제외 환경변수에만 저장하며 브라우저에
노출하지 않는다.

### 5.1 지역 검색 API에서 제공되는 정보

공식 API 명세상 지역 검색 결과에는 업체명, 링크, 분류, 설명, 지번 주소,
도로명 주소와 좌표가 포함될 수 있다. 전화번호 필드는 존재하지만 값은 제공되지
않는다. 한 질의는 최대 5건이고 `start`는 1로 제한된다.

### 5.2 웹문서 검색 API에서 제공되는 정보

웹문서 검색 결과에는 문서 제목, URL과 검색 요약문이 포함된다. 한 질의는 최대
100건, 시작 위치는 최대 1000까지 지원된다.

### 5.3 실제 파일럿 처리 흐름

1. 서울·경기 하위 지역과 `탐정사무소`, `흥신소`, `민간조사` 등의 검색어 조합
2. 지역 API 결과를 만료 시각이 있는 비공개 원시 후보로 7일 임시 저장
3. 상호·주소·URL을 정규화하고 기존 DB와 중복 제거
4. 웹문서 API로 업체 공식 홈페이지 후보를 추가 검색
5. 공식 URL의 공개 IP·HTTPS·redirect·robots·응답 상태·크기를 코드로 확인
6. 정책 확인을 통과한 공식 페이지에서 원문을 저장하지 않고 상호·
   업무용 대표번호·주소와 탐정 업무 문구를 코드로 추출
7. 업체 관련성, 강한 사실 일치, 전화, 공식 페이지 업무 증거와 기존 DB 중복을
   결정론적으로 검사해 비공개 수동 검토·추가 조사·제외로 분리
8. 기존 사전검증과 관리자 승인 전에는 DB 적재·공개 금지

이 흐름은 API 검색결과 자체를 사용자에게 네이버 검색결과로 표시하려는 것이
아니라, 내부 업체 발굴·필터링과 공개 디렉터리 데이터 확보에 사용하려는
목적이었다. 2026-08-21 현재 실제 API 응답·filtered 파일·사실 레코드 자체를
AI 모델 입력으로 제공하지 않았고, 명령 출력에는 업체 값이 아닌 집계만 사용했다.

### 5.4 2026-08-21 실제 실행 규모와 보존 상태

- 지역 API: 368회, 비공개 Raw 1,566건
- 웹문서 API: 478회, 제목·URL만 담은 비공개 Raw 1,984건
- 공식 URL 정책·응답 확인: 130건
- 원문 비보존 최소 사실 추출: 84건
- 사실 판정: 강한 일치 27건, 부분 일치 30건, 정보 부족 24건, 실패 3건
- 최초 업체 정체성 중복 제거 수동 검토 큐: 39곳. 무관 업종 오탐을 발견해
  폐기 대상으로 전환
- API 재호출 없는 v3 지역 재필터: Raw 1,566건 중 `needs_review` 588건,
  `rejected` 956건, `source_check_required` 22건
- 공식 페이지 탐정 업무 문구 확인: 23건
- 수정된 최종 수동 검토 큐: 1곳, 추가 조사 큐 23곳, 알려진 무관 후보 0곳
- 저장 위치와 권한: Git 제외 `data/private/discovery-runs`, 디렉터리 `0700`,
  파일 `0600`
- 기본 만료: 7일이며 새 실행 전 만료 파일 자동 파기
- DB·Production 반영: 0건

웹 검색 실행 이력에는 부모 레코드 ID와 후보 정체성 해시를 남겨 같은 업체를
다른 검색어로 반복 호출하지 않는다. 수정된 수동 검토·추가 조사 큐도 각각
`review_status=pending`, `review_status=research_required`이고 모두
`promotion_allowed=false`이며 기존 office batch manifest로 자동 변환되지
않는다.

## 6. 확인한 NAVER API 관련 조건

이 절은 약관을 해석한 법률 결론이 아니라 공식 문서에서 확인한 사실을 요약한
것이다. 실제 적용 약관은 NAVER API HUB 가입 시 동의한 문서와 이후 개정,
NAVER Cloud Platform 공통 약관을 함께 확인해야 한다.

### 6.1 현재 확인 가능한 기존 조건

공개된 NAVER API 서비스 약관에는 다음 취지의 조건이 있다.

- 인증 키와 결과 데이터를 무단 복제·저장·가공·배포하거나 제3자에게 전송하는
  경우 키 제한 또는 서비스 중단 가능
- 검색 결과를 독립적으로 표시하고 결과의 순서·내용·URL을 왜곡하지 않을 의무
- API는 비상업적 목적으로만 이용하고 광고와 결합·인접하지 않도록 하는 조건
- 검색 결과에 관한 권리는 네이버 또는 제3자에게 있고 API 이용 승인만으로
  별도 권리를 취득하지 않음

### 6.2 2026-09-07 시행 예정 개정

네이버의 2026-08-07 공지에 따르면 검색 API 특약은 2026-09-07부터 다음과 같이
강화될 예정이다.

- 검색 API는 애플리케이션에서 네이버 검색 결과를 제공하는 목적으로만 이용
- 네이버 BI와 원본 출처·이동 링크 표시
- 데이터를 독립적이고 가공하지 않은 상태로 표시
- 검색 결과 및 가공·파생물을 복사, 저장 또는 캐싱하는 행위 제한
- 제3자 제공·판매 제한
- 데이터를 AI에 입력하거나 학습·개선·평가·노출 등에 활용하는 행위 제한
- 검색 결과가 표시되는 페이지의 광고 및 검색 API를 이용한 수익 활동 제한
- 예외적인 임시 캐시는 목적별로 기기는 최대 24시간 또는 새 질의 시점 중 더
  짧은 기간, 서버 이력 조회는 최대 21일 등으로 제한

이 조건을 문언대로 적용하면 내부 후보 발굴, 정규화, 중복 제거, 장기 저장,
AI 검수와 광고형 디렉터리 데이터 확보는 모두 별도 확인이 필요한 고위험
영역으로 보인다.

## 7. 계획과 약관 사이의 쟁점

| 계획된 행위 | 확인이 필요한 이유 |
| --- | --- |
| 지역·웹문서 API 결과를 JSONL 또는 DB에 저장 | 검색 결과 및 파생물의 저장·캐싱 제한과 충돌 가능 |
| 상호·주소·URL을 정규화하고 중복 제거 | 가공·파생물 제한에 해당할 가능성 |
| API 결과를 AI 에이전트에 전달해 최종 후보 판단 | 2026-09-07부터 명시적인 AI 입력 제한 가능성 |
| 검색 결과를 공개하지 않고 내부 발굴에만 사용 | 검색 결과 제공 목적만 허용하는 조건과 불일치 가능 |
| API 결과로 찾은 공식 사이트를 다시 확인해 별도 사실 데이터 생성 | 공식 사이트의 독립 출처 확인으로 API 데이터와 법적·계약상 연결이 단절되는지 불명확 |
| 최종 공개 화면에 네이버 BI나 원본 결과 링크를 표시하지 않음 | API 데이터 사용으로 평가되면 표시 의무 위반 가능성 |
| 광고·강화 상품이 있는 디렉터리에 업체 정보 게시 | 검색 API를 활용한 수익 행위 제한에 해당할 가능성 |
| 검색 결과의 링크·검색어·해시·제외 사유만 보관 | 원본의 일부 또는 파생물에 해당하는지 불명확 |
| 21일 안에 원시 결과를 삭제하고 공식 출처 정보만 유지 | 허용된 서버 캐시 목적이 `이력 조회`로 한정되는지, 발굴 목적에 적용 가능한지 불명확 |

## 8. 전문가에게 확인하고 싶은 질문

1. NAVER API HUB의 지역·웹문서 API를 공개 검색결과 표시가 아니라 내부 업체
   후보 발굴에 사용하는 것이 현재 및 2026-09-07 개정 약관상 허용되는가?
2. 검색 결과에서 업체명·주소·링크만 읽고 즉시 공식 홈페이지를 방문한 뒤 API
   응답을 폐기하면 허용되는가?
3. 공식 홈페이지에서 상호·주소·전화번호를 독립적으로 재확인하고 공식
   홈페이지만 공개 출처로 표시하면, 최종 데이터는 검색 API 결과 또는
   파생물과 구분될 수 있는가?
4. 검색 결과의 후보 URL을 정규화·중복 제거·점수화하는 행위가 금지된 `가공`
   또는 `파생물` 생성에 해당하는가?
5. API 응답 자체를 AI에 전달하지 않고, 사람이 공식 홈페이지에서 다시 확인한
   별도 사실만 AI가 검수하는 것은 허용되는가?
6. API가 제공한 링크를 통해 방문한 공식 홈페이지의 내용을 AI가 검수하는
   경우에도 API 데이터를 AI에 입력한 것으로 볼 여지가 있는가?
7. API 원시 응답은 저장하지 않고 질의, 호출 시각, HTTP 상태, 결과 건수,
   중복·제외 건수만 보관할 수 있는가?
8. 링크, 상호, 주소, 좌표 또는 그 해시 중 어떤 정보가 검색 결과 데이터 또는
   파생물로 취급되는가?
9. 서버의 최대 21일 임시 캐시 예외를 후보 검수 이력에 적용할 수 있는가, 아니면
   사용자에게 검색 이력을 보여주기 위한 목적에만 한정되는가?
10. 광고·업체용 강화 상품을 별도 화면이나 별도 모듈에서 제공하더라도, 검색
    API가 업체 발굴에 사용됐다면 금지된 수익 활동에 해당하는가?
11. 네이버 검색 결과를 사용자에게 표시하지 않는 내부 사용에도 BI, 원본 출처와
    원본 이동 링크 표시 의무가 적용되는가?
12. NAVER API HUB 신청 과정에서 동의한 별도 약관이 기존 NAVER API 서비스
    약관 및 2026-09-07 개정 공지와 어떤 우선순위로 적용되는가?
13. 네이버 또는 NAVER Cloud Platform에서 서면 허가나 별도 상업 이용 계약을
    받을 수 있는가? 가능하다면 허가 범위에 내부 발굴·저장·가공·AI 검수·광고
    디렉터리를 명시해야 하는가?
14. 검색 API를 사용하지 않고 일반 검색을 사람이 수행한 뒤 각 업체 공식
    홈페이지의 공개 사실만 최소한으로 저장·게시하는 현재 방식에는 어떤
    약관·저작권·데이터베이스권·부정경쟁·개인정보 위험이 남는가?
15. 업체명, 사업장 주소와 업무용 대표번호 같은 사실 정보를 공식 홈페이지에서
    재확인해 제공할 때 필요한 출처 표시, 정정·삭제 요청, 보존 기간과 옵트아웃
    절차는 무엇인가?

## 9. 전문가 확인 전 임시 운영 결정

2026-08-20 운영자는 현재 상업 기능을 운영하지 않는 점을 전제로 제한적인 지역·
웹문서 API 수집과 결정론적 필터 파일럿 진행을 결정했고 2026-08-21 확대 실행을
완료했다. 이는 약관상 허용된다는 법률 판단을 뜻하지 않으며 다음 경계를
적용한다.

- 실제 결과는 Git 제외 `data/private/discovery-runs`에 기본 7일, 최대 21일의
  만료 시각을 붙인 비공개 JSONL로만 저장한다.
- 후속 Raw v2는 제목·링크·분류·주소만 저장하며 설명·전화번호·좌표를 저장하지
  않는다. 기존 Raw v1은 최초 보존기한 내 재필터 호환만 유지한다.
- 새 API 실행 전 만료 실행을 자동 파기하고 별도 파기 명령을 제공한다. 만료되거나
  만료 시각이 잘못된 Raw는 재필터하지 않는다.
- 실행당 요청은 기본 30회, 절대 100회로 제한하고 일시 오류 재시도도 포함한다.
- 지역·관련성·중복·링크 유형의 설명 가능한 규칙만 적용한다.
- NAVER API HUB 결과나 filtered 파생 파일을 AI 모델에 입력하지 않는다.
- API 결과를 manifest, 공개 업체 데이터, Production 또는 광고 화면에 반영하지
  않는다.
- 지역 결과 중 공식 링크 없음·비공식 링크·HTTP 링크 사유가 있는 비반려 후보만
  웹문서 API로 재검색했다. 웹 Raw에는 제목·URL만 저장하고 설명문·질의문은
  저장하지 않으며 부모 지역 Raw보다 오래 보존하지 않는다.
- 공식 홈페이지의 최소 사실 재확인은 NAVER 응답과 분리한다. robots와 응답
  정책을 통과한 페이지에서 원문을 저장하지 않고 상호·업무용 대표번호·주소만
  코드로 추출하며, 그 결과도 수동 검토 전에는 DB나 공개 데이터로 변환하지 않는다.
- 2026-09-07 개정 약관 시행 또는 상업 기능 도입 전 전문가 의견과 NAVER Cloud
  Platform 고객지원의 서면 답변을 확보하지 못하면 실제 호출·저장을 중단한다.

## 10. 제한된 기술 시험 범위

전문가 검토 전에 수행할 시험은 다음으로 제한한다.

- 지역 검색 API 1회, 웹문서 검색 API 1회
- 각 요청 결과는 프로세스 메모리에서 즉시 폐기
- 파일·DB·로그에 검색 결과의 제목, URL, 주소, 설명, 좌표를 기록하지 않음
- AI에는 HTTP 성공 여부, 응답이 JSON인지, 최상위 필드명과 배열 크기처럼 실제
  검색 결과 내용을 복원할 수 없는 기술 상태만 전달
- 테스트 후 자동 수집·후보 생성·공개 작업은 수행하지 않음

### 10.1 2026-08-20 제한적 파일럿 실행 기록

운영자 결정에 따라 위 최초 2회 스키마 시험 뒤 지역 API 수집·결정론적 필터
파일럿을 추가로 실행했다.

- 대상: 서울 관악·광진, 경기 광명·구리와 검색어 2개 조합
- API 호출: 지역 검색 8회
- Raw 결과: 40건, Git 제외 JSONL, 파일 권한 `0600`
- 보존 표시: 7일, 2026-08-27 만료
- 재필터: API 추가 호출 없이 동일 Raw 사용
- 결과: `eligible` 1건, `needs_review` 32건, `rejected` 7건
- 주요 사유: 공식 링크 없음 33건, 실행 내부 중복 6건, 관련성 재검토 10건
- 실제 업체명·주소·URL·설명: AI 출력, Git, 공개 DB와 Production에 미전달
- 공개 업체·검수 후보·Production: 변경 없음

이 실행은 약관상 허용된다는 결론이 아니라 현재 비상업 단계에서 운영자가 정한
제한적 기술 파일럿이다. `eligible`도 공식 출처 재확인이나 공개 승인을 의미하지
않는다.

### 10.2 파일럿 후속 hardening

첫 실행 뒤 오해 소지가 있는 `eligible` 상태를 `source_check_required`로 바꿨다.
새 filtered v2 레코드는 모두 `source_verification=required`,
`promotion_allowed=false`이며 검색 결과를 업체 manifest로 직접 변환하는 명령은
제공하지 않는다. 공식 홈페이지에서 독립적으로 확인한 값만 기존 manifest·
사전검증·관리자 승인 절차에 입력할 수 있다. 이 변경은 약관상 이용 허용 여부를
판단하거나 보장하지 않는다.

### 10.3 웹문서 후보 재검색·네트워크 점검 기록

2026-08-20 운영자 결정에 따라 지역 Raw에서 공식 링크 없음·비공식 링크 후보
10건만 웹문서 API로 재검색했다.

- API 호출: 웹문서 검색 10회
- Raw 결과: 제목·URL만 45건, 설명문·질의문 미저장
- 필터 결과: `source_check_required` 7건, `needs_review` 29건, `rejected` 9건
- URL 네트워크 점검: 본문 대조 대상 3건, robots 차단 1건, 응답 크기 초과 보류
  3건
- 보존: 부모 지역 Raw와 같은 2026-08-27 만료
- AI·Git·DB·Production 전달: 없음

네트워크 점검 통과는 공식 홈페이지나 업체 정보의 진실성을 확인했다는 뜻이
아니다. 통과 3건도 `content_check_required`, `source_verification=required`,
`promotion_allowed=false`이며 공식 원문의 상호·주소·대표번호를 별도로 확인해야
한다.
