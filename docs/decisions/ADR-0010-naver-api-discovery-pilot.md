# ADR-0010: NAVER API HUB 지역 후보 발굴 제한적 파일럿

- 상태: 제한적 승인
- 결정일: 2026-08-20
- 재검토 기한: 2026-09-06 또는 상업 기능 도입 전 중 더 이른 시점

## 맥락

현재 업체 데이터 확대는 일반 웹 검색으로 후보를 찾고 공식 홈페이지의 최소
사실을 사람이 재확인한 뒤 배치 사전검증과 관리자 승인을 거친다. 개발 DB 공개
업체 64곳 이후에도 같은 수작업 발견을 반복하면서 후보 발굴과 초기 중복 제거에
시간과 AI 토큰이 많이 든다.

2026-08-20 NAVER API HUB Application에 지역·웹문서 검색 API와 서버 전용 키를
준비했다. 지역 API는 네이버 지역 서비스의 업체명, 분류, 주소, 링크와 좌표를
한 질의당 최대 5건 반환하지만 전화번호는 반환하지 않는다.

한편 2026-09-07 시행 예정 NAVER 검색 API 특약은 검색 결과 및 파생물의 저장·
가공, 제3자 제공, AI 입력과 수익 목적 이용을 제한한다. 현재 서비스는 아직
상업 기능을 운영하지 않지만 저장·가공·AI 제한은 상업성 외의 별도 쟁점이다.
운영자는 전문가 검토 요청서를 준비한 상태에서 현재 비상업 단계의 제한적인
수집·필터 파일럿 진행을 결정했다.

## 결정

- Python 수집기에 NAVER API HUB 전용 HTTP 클라이언트를 추가한다.
- 인증 정보는 `NAVER_API_HUB_CLIENT_ID`, `NAVER_API_HUB_CLIENT_SECRET` 서버
  환경변수로만 받고 값이나 응답 원문을 로그에 출력하지 않는다.
- 최초 파일럿은 지역 API만 호출했다. 후속 hardening 뒤 운영자 결정에 따라 지역
  결과 중 공식 링크 없음·비공식 링크·HTTP 링크 사유가 있는 비반려 후보만
  웹문서 API로 제한적으로 재검색할 수 있다. 웹 검색 Raw에는 제목·URL만 저장하고
  검색 설명문과 질의문은 저장하지 않으며 부모 지역 Raw보다 오래 보존하지 않는다.
- 실행당 API 요청 예산은 기본 30회, 절대 최대 100회다. 일시 오류 재시도도 이
  예산에 포함하며 요청당 최대 시도는 2회다.
- 실제 결과는 Git 제외 경로인 `data/private/discovery-runs`의 Raw JSONL에만
  저장하고 기본 7일, 최대 21일의 `expires_at`을 각 레코드에 기록한다. 새 API
  실행 전에는 만료 실행을 자동 파기하며 별도 파기 명령도 제공한다. 만료되거나
  만료 시각이 잘못된 Raw는 재필터하지 않는다.
- Raw v2에는 후보 발견과 중복 검사에 필요한 제목·링크·분류·주소만 저장하고
  설명·전화번호·좌표는 저장하지 않는다. 기존 Raw v1은 보존기한 내 재필터
  호환만 유지하며 사용하지 않는 필드는 읽는 즉시 버린다.
- Raw와 별도로 정규화된 이름·주소·URL, 상태와 사유 코드만 담은 filtered JSONL을
  만든다.
- 결정론적 규칙은 서울·경기 여부, 탐정 관련 상호·분류, 실행 내부 중복, 기존 DB
  이름·주소·출처 중복, 출처 등록부 host, 공식 링크 필요 여부만 판정한다.
- API 결과와 filtered 파일은 AI에 입력하지 않는다. CLI와 작업 결과에는 실제
  업체명·주소·URL 대신 건수와 사유 코드 집계만 노출한다.
- `source_check_required`는 API상 발견 후보일 뿐 공식 업체나 공개 후보가
  아니다. 모든 filtered 레코드는 `source_verification=required`,
  `promotion_allowed=false`로 고정한다. 공식
  홈페이지의 정책·원문을 별도로 재확인하고 기존 manifest·preflight·Clerk
  관리자 승인 경계를 통과하기 전에는 운영 DB에 적재하거나 공개하지 않는다.
- 웹문서 결과도 HTTPS·링크 유형·실행 내 중복·기존 출처·출처 등록부·후보명
  일치 신호만 결정론적으로 검사한다. 검색 결과 설명문이나 Raw/filtered 결과는
  AI에 입력하지 않으며 공식 홈페이지 원문 확인을 대신하지 않는다.
- 웹문서 결과 중 `source_check_required` URL은 공개 IP·HTTPS·동일 사이트
  redirect·robots·응답 상태·크기 제한을 원문 저장 없이 점검한다. 통과 결과도
  `content_check_required`, `source_verification=required`,
  `promotion_allowed=false`로 유지한다.
- 웹 검색 실행에는 선택한 부모 레코드 ID와 후보 정체성 해시만 담은 만료
  manifest를 남긴다. 검색 결과가 0건이거나 다른 검색어에서 다시 발견된
  후보도 보존기한 안에는 중복 호출하지 않는다.
- `content_check_required` 공식 페이지는 원문을 보존하지 않고 JSON-LD와 보이는
  HTML에서 상호·업무용 대표번호·주소 신호만 추출할 수 있다. 결과는 강한 일치,
  부분 일치, 정보 부족, 실패로 분리하고 항상 `promotion_allowed=false`다.
- 강한/부분 일치 facts는 정체성 해시로 중복 제거한 수동 검토 큐로 합칠 수
  있지만, 이 큐를 운영 manifest나 DB로 자동 변환하지 않는다.
- Production, 광고 화면, 검색 결과 사용자 노출에는 사용하지 않는다.

## 결과

장점:

- 검색·중복 제거를 코드로 반복해 후보 발굴의 수작업과 토큰 사용을 줄일 수 있다.
- 실제 결과와 공개 데이터를 격리하고 실행별 요청 수·필터 사유를 재현할 수 있다.
- API 키와 실제 결과가 CI, Git, 브라우저 또는 일반 로그에 노출되지 않는다.

단점과 위험:

- 비상업 상태라도 검색 결과의 내부 저장·가공이 현재 또는 개정 약관의 허용
  범위를 벗어날 수 있다.
- 2026-09-07 개정 시행 뒤 같은 파일럿을 계속 운영할 수 있다고 가정할 수 없다.
- API 결과를 AI가 직접 보지 않으므로 최종 공식 출처 확인 자동화는 별도 설계가
  필요하다.
- 새 API 실행 전과 명시적 파기 명령에는 자동 파기가 적용되지만, 수집기가 전혀
  실행되지 않는 기간에도 만료 시각에 맞춰 지우려면 별도 예약 실행이 필요하다.

## 재검토 조건

다음 중 하나라도 발생하면 실제 API 호출과 결과 저장을 중단하고 결정을
재검토한다.

- 2026-09-07 개정 약관 시행
- 광고, 강화 상품, 유료 계약 등 상업 기능 운영 시작
- NAVER 또는 NAVER Cloud Platform의 중단·삭제·정정 요청
- 전문가 또는 NAVER Cloud Platform의 서면 답변 수신
- Raw 자동 파기 명령의 예약 실행과 실패 감시 없이 서버 정기 수집을 도입하려는 경우
- API 결과 또는 그 파생물을 AI, 공개 화면, Production 데이터에 전달하려는 경우

관련 사실과 질문은
