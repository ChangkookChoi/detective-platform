# ADR-0002: Next.js App Router 모듈형 모놀리스

- 상태: 승인
- 결정일: 2026-07-22

## 맥락

MVP에는 공개 디렉터리, SEO 친화적 목록·상세, 관리자 검수, 초기 API가 필요하다. 팀과 트래픽 규모가 작고 기능 간 데이터 일관성이 중요하다. 별도 프론트엔드와 백엔드 또는 마이크로서비스는 배포·인증·관측성 비용을 늘린다.

## 결정

`apps/web`을 Next.js App Router 기반 모듈형 모놀리스로 구현한다. 공개 웹, 관리자 화면, Route Handler와 서버 측 유스케이스를 하나의 배포 단위에 두되 디렉터리, 검수, 수집 계약, 분석, 수익화의 모듈 경계를 유지한다.

- React Server Component를 기본으로 사용한다.
- 공개 핵심 콘텐츠를 서버 생성 HTML에 포함한다.
- 클라이언트 상호작용이 필요한 부분만 작은 Client Component로 만든다.
- Route Handler와 Server Action은 얇게 유지한다.
- Python 수집기는 별도 프로세스로 유지하며 검수 후보만 전달한다.
- Spring Boot와 마이크로서비스는 도입 전 별도 ADR을 요구한다.

## 결과

장점:

- 한 프레임워크에서 렌더링, 관리자, API를 빠르게 개발한다.
- 타입과 도메인 규칙을 공유하기 쉽다.
- 공개 페이지 SEO와 초기 운영 복잡도를 함께 관리할 수 있다.

단점:

- 모듈 규율이 없으면 프레임워크 파일에 비즈니스 로직이 섞일 수 있다.
- 한 배포의 장애나 변경이 여러 기능에 영향을 줄 수 있다.
- 장기 실행 수집 작업은 Next.js 요청 수명에 적합하지 않아 별도 실행이 필요하다.

## 대안

- SPA + 별도 API 서버: 독립성은 있지만 초기 배포·인증·SEO 구현 비용이 크다.
- Spring Boot 백엔드: 성숙한 서버 생태계를 제공하지만 현재 규모에서는 언어와 운영 단위가 불필요하게 늘어난다.
- 초기 마이크로서비스: 독립 배포는 가능하지만 분산 트랜잭션, 네트워크, 관측성 비용이 이르다.

## 재검토 조건

명확한 독립 확장 요구, 팀 소유권 분리, 배포 충돌, 격리해야 할 장애 또는 규제 경계가 반복적으로 확인될 때 분리를 검토한다. 분리 전 모듈 의존성과 데이터 소유권을 측정하고 ADR을 작성한다.
